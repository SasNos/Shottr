# Shottr

Chrome extension (Manifest V3, no build step, no runtime dependencies; the dev dependencies are only the linters and the formatter).

## Features

- **Full page**: scrolls the page (or the app's main scroll area) and stitches the screenshots. Only the page content is captured, never the browser UI.
- **Selected area**: drag a frame, then adjust it (eight handles to resize, drag inside to move) and confirm with Enter, the Capture button or a double click. Copy (or Ctrl+C, Cmd+C) puts the area straight on the clipboard as PNG without opening the editor; where the page cannot (http pages have no clipboard access), the editor opens briefly, copies the area and closes again. Esc cancels.
- **Selected area with DevTools**: for areas that include the DevTools or other parts of the window. Chrome asks which window to share, Shottr takes one picture of it, and the area is selected on that picture (same handles and keys as above). The page screenshot functions of Chrome never contain the DevTools, so this mode needs the desktop capture dialog every time.
- **Visible part**: the current viewport.
- **Editor** after every capture, opened in a new tab right next to the page (closing it returns to the page), preview in the real size of the page: pen, hollow rectangles and ellipses (in the pen color), comments, undo, redo, clear.
  - Color picker and stroke width 1 to 5 px.
  - Comments: black text on a white box. The box is resizable (down to one character wide) and wraps text; bold, italic and font size (10 to 48 px) apply to the whole comment.
- **Cancel**: Esc during the area selection or during a full page capture aborts it; Cancel (or Esc) in the editor closes the tab, with a confirmation when there are annotations.
- **Output**: download as PNG, WebP or PDF (single page, sized to the screenshot), copy to the clipboard (PNG), or share through the system share sheet (shown only when the browser supports sharing files).

## Install (development)

1. Open `chrome://extensions`, enable _Developer mode_.
2. _Load unpacked_ and select this folder.

## Update

Chrome loads the extension from this folder, so the folder has to be current before Chrome can pick up a new version. Register the folder once for automatic updates (PowerShell, in this folder):

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\auto-update.ps1 -Install
```

A scheduled task then runs `git pull --ff-only` at logon and every 15 minutes; local changes are never touched, and `-Uninstall` removes the task. A new version then takes one click: open `chrome://extensions` (Developer mode) and click _Update_, or the reload icon of Shottr. Updates and failures are logged to `%LOCALAPPDATA%\Shottr\auto-update.log`.

## Develop

```bash
npm install       # once: ESLint, Stylelint and Prettier
npm test          # the tests with a 100% line, branch and function threshold
npm run lint      # ESLint (JS), Stylelint (CSS)
npm run format    # Prettier and the auto-fixable lint rules (format:check only checks)
npm run tokens    # regenerates src/theme.css and fonts/ from Mber Flow (tokens:check only checks)
npm run check     # lint, format check, tokens check and tests; green before every commit
npm run icons     # regenerate icons/ (only needed when the icon design changes)
```

## Limitations

- Full page scrolls the document, or, when the document cannot scroll, the largest scrolling element that fills at least 40 % of the window. Several scroll areas side by side are not combined; only the largest is captured.
- Fixed and sticky elements appear in the first tile only; they are hidden while the remaining tiles are captured.
- Pages are capped at 30000 CSS px of height; the stitched image is scaled down if it exceeds the canvas limits of Chrome (16384 px per side).
- Chrome does not allow capturing `chrome://` pages and the Chrome Web Store; the toolbar button then shows a `!` with the reason as tooltip.
- PDF pages are limited to 14400 pt; taller screenshots are scaled down to fit.

## Spark

Shottr is built into the browser Spark as a tool; the pipeline and the editor take their Chrome access through the hosts in `src/hosts/`, so Spark can supply its own. See [docs/SPARK.md](docs/SPARK.md).

## Design

The look comes from Spark, which takes its design system from Mber Flow (`Tools\Mber Web\Mber Flow`): `src/theme.css` is generated by `npm run tokens` (`tools/tokens.mjs`, the token names in `tokens.config.json`; never edit it) with the Mber Flow tokens (spacing on the 4 px grid, type scale, control heights, radii, colors for light and dark) and the fonts Figtree (headings) and Open Sans (text) from `fonts/`. `src/base.css` adds Shottr's motion tokens, the heading font, the focus ring and reduced motion. The other stylesheets use only these variables; Stylelint rejects hex and named colors and px values for font sizes, spacing and radii. The selection bar and the toast run inside web pages, so they carry a few token values in JavaScript and keep the system font; `test/inpage-theme.test.js` keeps those values equal to `theme.css`. Rules: `docs/STYLEGUIDE.md` in Mber Flow.

## Layout

- `src/capture.js`, `src/content.js`: capture pipeline and page script, independent of Chrome.
- `src/hosts/`: the Chrome side of the pipeline and the editor (`chrome.scripting`, `captureVisibleTab`, `chrome.storage`, tabs, the desktop capture for the window, whose frame is grabbed in the captured page).
- `src/background.js`, `src/popup.*`, `src/editor-main.js`: the extension shell.
- `src/stitch.js`, `src/layout.js`: tile stitching and cropping.
- `src/editor*.js`, `src/annotations.js`: preview and annotation editor.
- `src/theme.css` (generated), `src/base.css`, `src/theme.js`: design tokens, shared rules and the light or dark switch; `fonts/`: Figtree and Open Sans; `tools/tokens.mjs`: the token sync.
- `src/clipboard.js`: the PNG for Copy in the selection bar.
- `src/export.js`, `src/pdf.js`: PNG, WebP and PDF output (the PDF writer is built in).
- `test/`: unit tests with browser API doubles in `test/helpers/`.
